# PNCW v0.2 GCM-Guided Projection Planning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic, conformance-gated GCM Phase-B planning plane that selects among explicit projection routes, compiles the accepted route into the existing `ProjectionRequestV1`, and reuses the sealed PNCW v0.1.0 readiness/verification/visibility kernel unchanged.

**Architecture:** v0.2 adds new planning contracts, canonical identities, a `GcmPlanningPort`, a conformance-gated `PlanAcceptanceGate`, a pure `ProjectionRequestCompiler`, deterministic replan lineage, and fake/real GCM adapters. The production adapter communicates with a clean installed GCM Phase-B wheel over a versioned JSONL local-process boundary; PNCW never imports GCM private internals and GCM never receives PNCW `AuthorityContextV1`.

**Tech Stack:** Node.js `>=22.5.0`, TypeScript `5.8.3`, ESM/NodeNext, `node:test`, Ajv `8.18.0` Draft 2020-12, Python 3 for the real GCM host, sealed `gcm_runtime` Phase-B installed wheel for real validation.

**Spec:** `docs/superpowers/specs/2026-08-30-pncw-v0.2-gcm-guided-projection-planning-design.md`

## Global Constraints

- Start implementation from `main@003cce0a5f4c35b7870850af66c883b856da7ea1`; the sealed runtime baseline remains `v0.1.0@121bc1024277e7e21a14e8e1a92eed7dba02400d`.
- Do not modify the `v0.1.0` tag or reinterpret `ProjectionRequestV1`, RID, MID, VID, VCID, `ProjectionReadinessGate`, `ProjectionVerifier`, live verification proof, or `VisibilityCommitStore`.
- Use strict TDD: write a failing behavioral test, run it and verify the intended failure, write the smallest production change, rerun the focused test, then run the relevant regression set before committing.
- Every v0.2 planning JSON Schema is Draft 2020-12, closed at every modeled object boundary, and validated with Ajv 2020 strict mode in CI.
- Identity-bearing non-integer planning numbers use canonical decimal strings. Bounded count fields use exact integers in `[1, 2147483647]`.
- Host-language float formatting must never participate in CID/BID/FID/PPRID/GPD/PPID computation.
- `PlanningAuthority != SourceAuthority != SurfaceAuthority != VisibilityAuthority`.
- GCM-native authority/admissibility evidence remains opaque to PNCW and must never be translated into `sourceRead`, `surfaceProject`, visibility authority, commit authority, or writer capability.
- `PPID != RID`; different planning provenance may compile to the same semantic projection and therefore the same RID.
- GCM Phase C is not a v0.2 production dependency.
- The real GCM adapter may use only installed Phase-B public APIs and a versioned public-API support profile; unsupported public signatures fail closed instead of falling back to private imports.
- Production plan acceptance requires GCM allocator conformance claim exactly `CONFORMANT` for profile `R0-M4`.
- GCM logical allocation is not physical CPU/GPU/NPU reservation.
- A selected route that becomes stale/unavailable/conflicting after planning triggers fresh replan; never silently select another candidate from an old feasible set.
- `npm ci`, `npm run check`, `npm test`, and `npm audit --audit-level=moderate` remain mandatory release-line gates.
- No v0.2 task may claim natural-language goal decomposition, autonomous AI planning, canonical HDSRC writeback, governed actuation, or full perception-action closure.
