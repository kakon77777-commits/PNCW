```text

→ ProjectionReadinessGate
```

Preserved invariants:

```text

Visible != Resident
Identity != Authority
STALE_SOURCE != INTEGRITY_FAILURE
Digest Agreement != Structural Semantic Validity
Source Authority != Surface Authority != Visibility Authority
Visibility Commit != World Mutation Commit
```

v0.2 layers planning above this kernel. It MUST NOT reinterpret the sealed v0.1.0 semantics.

## 1.2 GCM baseline

PNCW v0.2 consumes sealed GCM Phase B — Deterministic Compute Allocator as the production planning/selection substrate.

Required Phase-B capability families:

```text
B1 — Intent / deterministic planning
B2 — Resource snapshot / binding
B3 — Capacity-constrained joint allocation
B4 — Multi-objective / Pareto / explicit policy selection
B5 — Allocation lifecycle / deterministic replanning
B6 — Allocator conformance / final seal
```

The design depends only on the Phase-B public, installed, deterministic API surface.

It MUST NOT depend on private allocator traversal internals, private SQLite tables, internal test registries, or private writer paths.

## 1.3 Phase C boundary

PNCW v0.2 does **not** depend on GCM Phase C.

The last Phase-C C1 independent inspection available during design review had identified a context-isolation blocker and did not establish a sealed Phase-C dependency.

Even if Phase C is later independently sealed, it remains above Phase B:

```text
AI Proposal
→ Deterministic Validation
→ Sealed Phase-B Allocator
```

Never:

```text

→ Direct PNCW Execution
```

# 4. Authority Model

v0.2 extends authority separation:

\[
\boxed{
PlanningAuthority
\neq
SourceAuthority
\neq
SurfaceAuthority
\neq
VisibilityAuthority
}
\]

GCM MAY select a projection candidate.

GCM MUST NOT:

```text
grant sourceRead
grant surfaceProject
mint AuthorityContextV1
grant commit authority
grant writer capability
grant visibility authority
write canonical HDSRC source
invoke PNCW VisibilityCommit
```

The original caller supplies PNCW `AuthorityContextV1`.

The planning layer MUST NOT modify it.

The compiler injects the **current caller authority** into the final `ProjectionRequestV1`.

v0.1.0 Readiness independently re-checks source and surface authorization.

\[
\boxed{
\text{GCM Selected}
\neq
\text{PNCW Authorized}
}
\]

## 4.1 GCM-native planning authority is separate

Sealed GCM Phase B may itself require GCM-native authority/admissibility evidence for allocator validity.

That GCM-native evidence belongs to the frozen GCM planning snapshot and is represented to PNCW only by a digest/reference.

It is NOT PNCW `AuthorityContextV1` and MUST NOT be translated into:

```text
sourceRead
surfaceProject
visibility authority
world mutation authority
```

Therefore:

\[
\boxed{
\text{GCM Native Planning Authority Evidence}
\neq
\text{PNCW Projection Authority}
}
\]

# 7. Canonical Decimal

Identity-bearing non-integer planning quantities use a canonical decimal string.

```ts
type CanonicalDecimalV1 = string
```

Valid examples:

```text
"0"
"1"
"16"
"0.25"
"1000.125"
```

Rejected examples:

```text
"01"
"1."
".5"
"1e3"
"-0"
"NaN"
"Infinity"
```

Rules:

```text
no exponent notation
no leading zero except "0"
no trailing fractional zeros
no trailing decimal point
no negative zero
finite values only
non-negative where domain requires
```

Identity-bearing count fields such as `maxCandidates` and `maxMaterializedRegions` use bounded JSON integers in `[1, 2147483647]` and therefore remain exactly representable in both supported host languages.

Rationale: v0.1.0 closure demonstrated host-language JSON floating serialization differences between Python and JavaScript.

\[
\boxed{
\text{Planning Identity}
\not\equiv
\text{Host Float Serialization}
}
\]

`candidateId` is a derived field, not arbitrary caller metadata.

Before hashing:

# 10. ProjectionDemandProfileV1

```ts
interface ProjectionDemandProfileV1 {
  demands: ProjectionDemandV1[]
}

interface ProjectionDemandV1 {
  dimensionId: string
  unit: string
  estimate:
    | { kind:'KNOWN', value: CanonicalDecimalV1 }
    | { kind:'BOUNDED', lower: CanonicalDecimalV1, upper: CanonicalDecimalV1 }
    | { kind:'ESTIMATED', value: CanonicalDecimalV1, hardSafe: boolean, provenance: string }
    | { kind:'UNKNOWN' }
}
```

Required mapping semantics:

```text
KNOWN(v)              → exact hard demand v
BOUNDED(lower, upper) → conservative hard demand upper
UNKNOWN               → fail closed for required hard demand
ESTIMATED(v)          → invalid as hard demand unless hardSafe=true
```

UNKNOWN MUST NOT be coerced to zero.

Unit conversion is not implicit. Unit mismatch fails closed unless an explicitly versioned future conversion contract is added.

# 41. v0.2 Acceptance Criteria

**AC-01 Contracts** — all planning schemas versioned and closed.

**AC-02 Canonical Numeric Form** — identity-bearing non-integer planning numbers use canonical decimals; bounded counts are exact integers.

**AC-03 Derived IDs** — candidateId, budgetId, frozenInputDigest, planningRequestId, planSnapshotDigest, and planningId are validated against self-excluding canonical payloads.

**AC-04 Candidate Determinism** — equivalent candidates produce identical CID.

**AC-05 Order Independence** — equivalent candidate sets with different insertion order produce identical candidate-set digest and PPRID.

**AC-06 Budget Fail-Closed** — UNKNOWN hard demand is never zero; unit mismatch fails closed.

**AC-07 Explicit Policy** — no silent priority, weight, normalization, or rescaling default.

**AC-08 GCM Conformance** — production plan acceptance requires exactly CONFORMANT sealed Phase-B identity.

**AC-09 Authority Isolation** — GCM cannot manufacture or modify PNCW source/surface/visibility authority; GCM-native authority evidence remains opaque and separate.

**AC-10 Plan Acceptance** — stale, mutated, mismatched, non-conformant, indeterminate, or authority-bearing plans are rejected.

**AC-11 Compiler Purity** — compiler preserves selected semantic projection exactly and injects only current caller authority.

**AC-12 PPID/RID Isolation** — `PPID_A != PPID_B` plus same semantic projection implies `RID_A == RID_B`.

**AC-13 Replanning** — execution-time invalidation requires fresh deterministic replan; no silent fallback.

**AC-14 Restart** — restart cannot manufacture new authority or reuse stale plan validity without required revalidation.

**AC-15 Fake Full Slice** — fake GCM → compiler → v0.1 kernel → VISIBLE passes.

**AC-16 Actual GCM Wheel** — installed sealed Phase-B wheel/process/conformance path passes.

**AC-17 Real E2E** — actual GCM selection → actual HDSRC/MRMIC → PNCW visibility slice passes.

**AC-18 v0.1 Regression** — all existing v0.1.0 tests remain green.

# 46. Self-Review Resolutions

The initial written draft was self-reviewed before user handoff. The following ambiguities were resolved in this canonical revision:

1. `candidateId`, `budgetId`, `planningRequestId`, `planSnapshotDigest`, and `planningId` are derived from self-excluding payloads; there is no self-referential hash.
2. `GcmPlanSnapshotV1` explicitly binds `candidateSetDigest`, `budgetDigest`, `policyDigest`, `frozenInputDigest`, and `selectedCandidateDigest`, allowing `PlanAcceptanceGate` to prove the selected route came from the same frozen planning input.
3. GCM conformance can represent `CONFORMANT`, `NONCONFORMANT`, and `INDETERMINATE`; only `CONFORMANT` is accepted.
4. `FrozenInputDigest` is explicitly defined as `FID`, not an ambiguous alias for another digest.
5. GCM-native planning authority/admissibility evidence is explicitly separated from PNCW `AuthorityContextV1`.
6. Upstream GCM allocation/policy digests are treated as opaque GCM semantic identities and are bound by the normalized PNCW plan snapshot rather than reinterpreted by TypeScript.
7. `compilerContractVersion` is known at plan acceptance and validated again by the compiler, avoiding stage-order ambiguity.

# 47. Final Design Statement

PNCW v0.2 is not a replacement for GCM and is not an AI allocator.

It is a planning-to-projection bridge.

Its responsibilities are:

1. present bounded projection candidates to a sealed deterministic GCM allocator;
2. preserve frozen planning inputs and canonical identities;
3. accept only conformance-valid, integrity-valid planning evidence;
4. compile the selected semantic projection without mutation;
5. inject current caller authority only at the PNCW boundary;
6. reuse the v0.1.0 readiness / verification / visibility kernel unchanged;
7. trigger deterministic replan instead of stale silent fallback.
